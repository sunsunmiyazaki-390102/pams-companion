# 1. 本書の目的

本書は、PAMS Companionが管理する情報と、その関係を定義する。

PAMS Companionは、AIとの対話ライフサイクル全体を支援し、対話から得られた情報を知識資産として蓄積し、次回以降のAI利用へ再利用する。

そのため、画面構成とは分離して、システムが管理するデータを明確にする必要がある。

本書は、今後のDjangoモデル設計、データベース設計、画面設計及びAPI設計の基礎資料とする。

---

# 2. データモデルの基本方針

PAMS Companionのデータモデルは、次の方針に基づいて設計する。

## 2.1 利用者中心

すべての情報は利用者に属する。

利用者は、自分の情報を確認、編集、保存、保管、削除及び書き出しできる。

---

## 2.2 AI非依存

ChatGPT、Gemini、Claudeなど、特定の生成AIに依存しないデータ構造とする。

利用したAIの名称は記録するが、データの保存形式はAIサービスごとに分離しない。

---

## 2.3 原文と整理結果の分離

AIへ渡した文章及びAIから受け取った回答の原文は、整理後の要点や知識資産とは分けて保存する。

これにより、後から整理内容を見直す場合でも、元の対話を確認できる。

---

## 2.4 利用者による承認

AIの回答から抽出された情報は、直ちに正式な知識資産として保存しない。

まず「候補」として作成し、利用者が確認、編集及び承認したものだけを正式に保存する。

---

## 2.5 履歴を失わない

重要な情報は物理的に直ちに削除せず、保管又は論理削除によって復元できる構造とする。

---

## 2.6 将来拡張への対応

MVPではコピーと貼り付けを中心とするが、将来のAI API連携、音声入力、複数端末同期及びPAMS Specificationとの連携を考慮する。

---

# 3. データモデルの全体構成

MVPでは、次の主要データを管理する。

1. 利用者プロフィール
2. プロジェクト
3. AI対話記録
4. 知識資産
5. 知識資産候補
6. 決定事項
7. TODO
8. 分類
9. タグ

# 4. データ関係の概念図

```text
利用者プロフィール
        │
        ├──────────────┐
        │              │
        ▼              ▼
  プロジェクト      AI対話記録
        │              │
        │              ├──────────────┐
        │              │              │
        ▼              ▼              ▼
    知識資産      知識資産候補     決定事項
        │              │              │
        │              │              ▼
        │              │             TODO
        │              │
        ├──────────────┘
        │
        ├── 分類
        │
        └── タグ
```

AI対話記録から、知識資産候補、決定事項及びTODOが生まれる。

知識資産候補は、利用者の確認と承認を経て正式な知識資産になる。

## 9.5 承認処理

利用者が候補を承認した場合、正式な `KnowledgeAsset` を作成する。

承認時には、次の内容を利用者が編集できる。

- タイトル
- 内容
- 分類
- プロジェクト
- 重要度

承認後も、元となった候補とAI対話記録との関連を保持する。

## 14.2 外部キーの削除方針

プロジェクト又はAI対話記録が削除された場合でも、知識資産、決定事項及びTODOを直ちに削除しない。

Djangoでは、関連情報を保持するため、原則として次のいずれかを使用する。

```python
on_delete=models.SET_NULL
```

または、

```python
on_delete=models.PROTECT
```

どちらを使用するかは、実装段階で各データの重要性に応じて決定する。

# 16. 成長の循環とデータの関係

PAMS Companionの成長の循環は、次のデータの連携によって実現する。

```text
過去の知識資産
        ↓
AIへ渡す文章へ再利用
        ↓
新しいAI対話記録
        ↓
新しい知識資産候補
        ↓
利用者による確認と承認
        ↓
正式な知識資産
        ↓
判断・決定・TODO
        ↓
プロジェクトの進展
        ↓
次のAI利用へ再利用
```

単にデータを保存するだけでは、成長の循環は実現しない。

保存した知識資産を、新しいAIへの質問作成時に簡単に選択して再利用できることが重要である。

# 20. プライバシー及び安全性

PAMS Companionは、利用者の知識、経験、判断基準及びAIとの対話を扱う。

そのため、データモデル設計では次の点を重視する。

- すべてのデータに所有者を設定する
- 他の利用者のデータを参照できないようにする
- 外部送信前に利用者が内容を確認できるようにする
- AIの回答を無条件に正式情報として保存しない
- 削除及び保管の状態を明確に区別する
- データを書き出せるようにする
- 不要な個人情報を収集しない
- APIキー等の秘密情報は、通常のデータとは分離して管理する

# 21. Django実装時の共通項目

複数のモデルで共通して使用する項目は、抽象基底モデルとしてまとめることを検討する。

例：

```python
class TimeStampedModel(models.Model):
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)

    class Meta:
        abstract = True
```

論理削除が必要なモデルでは、次のような共通モデルも検討する。

```python
class SoftDeleteModel(models.Model):
    deleted_at = models.DateTimeField(null=True, blank=True)

    class Meta:
        abstract = True
```

ただし、実装初期から過度に抽象化せず、必要性を確認しながら導入する。

# 23. まとめ

PAMS Companionのデータモデルは、AIとの対話そのものを保存するだけではなく、対話から得られた情報を知識資産へ変え、次回のAI利用へ再利用するために設計する。

MVPでは、次の四つを中核モデルとする。

```text
利用者プロフィール
プロジェクト
AI対話記録
知識資産
```

その後、知識資産候補、決定事項、TODO、分類及びタグを段階的に追加する。

PAMS Companionのデータモデルは、

- AIとの対話ライフサイクル
- 知識資産
- 成長の循環

という三つの中核概念を、実際のシステムとして実現するための基盤となる。
