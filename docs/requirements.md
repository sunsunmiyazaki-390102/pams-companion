# 1. はじめに

本書は、PAMS Companionの要求仕様を定義する。

PAMS Companionは、生成AIそのものを開発するものではなく、利用者が複数の生成AIをより効果的に活用し、AIとの対話を知識資産として育て続けることを目的としたAI利用支援プラットフォームである。

本書では、その目的を実現するために必要な要求を整理する。

---

# 2. 基本要求

## 2.1 人間中心

システムは、AIではなく利用者を中心として設計すること。

---

## 2.2 AI非依存

特定の生成AIへ依存せず、複数の生成AIで利用できること。

---

## 2.3 知識資産中心

利用者の知識資産を継続的に蓄積・活用できること。

---

## 2.4 継続利用

毎日自然に利用できる操作性を提供すること。

---

# 3. AIとの対話ライフサイクル要求

PAMS Companionは、次のライフサイクル全体を支援すること。

1. AIへ渡す情報を整理する
2. AIへ相談する
3. AIの回答を取得する
4. 回答を整理する
5. 知識資産として保存する
6. 必要に応じて再利用する
7. 次回のAI利用へ活用する

---

# 4. 機能要求

## 4.1 AIへ渡す情報

システムは、

利用者の

- プロジェクト
- 過去の経緯
- 判断基準
- 知識資産

などを整理し、

AIへ渡す文章を生成できること。

---

## 4.2 回答整理

AIから得られた回答から、

- 要約
- 決定事項
- TODO
- 知識資産候補

を抽出できること。

---

## 4.3 知識資産管理

知識資産を

- 保存
- 編集
- 検索
- 分類
- 再利用

できること。

---

## 4.4 プロジェクト管理

知識資産をプロジェクト単位で管理できること。

---

## 4.5 AI利用履歴

AIとの対話履歴を時系列で管理できること。

---

# 5. UX要求

利用者はPAMSの使い方を学習しなくても利用できること。

専門用語をできるだけ使用しないこと。

AI初心者でも迷わない画面構成とすること。

---

# 6. 成長支援要求

PAMS Companionは、

利用者がAIを利用するたびに、

知識資産を育て、

より良いAI活用ができるよう支援すること。

利用者の成長を継続的に支援することを最終目的とする。

---

# 7. 将来拡張要求

将来的に、

- OpenAI API
- Gemini API
- Claude API

などへ接続可能な構造とすること。

利用者自身のAPIキーを利用できる設計とすること。

---

# 8. MVP要求

MVPではAPI接続を行わない。

利用者が

コピー

↓

AIへ貼り付け

↓

回答をコピー

↓

PAMSへ貼り付け

だけで利用できること。

---

# 9. まとめ

PAMS Companionは、

AIを便利に利用するためのツールではない。

AIとの対話を通じて知識資産を育て、

利用者自身の成長を支援するプラットフォームである。

本要求仕様は、その目的を実現するための基本要求を定義するものである。
