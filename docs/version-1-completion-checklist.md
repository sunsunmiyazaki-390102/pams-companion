# PAMS Companion Version 1 完成条件チェックリスト

## 1. 文書の目的

この文書は、PAMS Companion Version 1 を一般利用者に公開できる状態にするため、
実装・動作確認・利用者視点での確認状況を整理するものである。

各項目を次の3段階で管理する。

- 完了：Version 1として必要な実装・確認が完了している
- 要確認：実装済みだが、公開前に確認または調整が必要
- 未完了：Version 1に必要だが、まだ実装または確認が完了していない

Version 2以降で実装する機能は、Version 1の未完了項目には含めない。


## 2. Version 1 の基本方針

PAMS Companion Version 1 は、

「AIと対話し、対話を振り返り、得られた内容を知識として整理し、
その知識を蓄積・検索・関連付けながら育てる」

という基本的な利用サイクルを、一般利用者がスマートフォン上で体験できることを完成条件とする。

Version 1では機能を増やし過ぎず、
現在実装されている中核機能を安全かつ分かりやすく利用できる状態で公開することを優先する。


# 3. 完成条件

## A. アプリの基本動作

### 完了

- FlutterアプリがAndroid実機で起動する
- 主要画面へ遷移できる
- SQLiteによるローカルデータ保存が動作する
- lutter analyze で問題が検出されない状態を維持している
- 修正単位ごとにGitで履歴を管理している


## B. ホーム画面・利用開始

### 完了

- ホーム画面から主要機能へ移動できる
- 初回利用者がホーム画面から迷わず使い始められる
- Version 1では「AIと考える」を最初の入口として案内する
- 「AIと考える」に
  「まずはAIと話してみましょう。」
  という利用開始を促す説明を表示する
- 実機でホーム画面の表示を確認済み


## C. AIとの対話

### 完了

- 「AIと考える」からAIとの対話を開始できる
- 新しい対話を作成できる
- AIとの対話内容を扱える
- 過去の対話を確認できる
- AI回答の状態を利用者に分かりやすい日本語で表示できる


## D. 対話の振り返り

### 完了

- AIとの対話を振り返る画面がある
- 対話内容から要約を扱える
- 対話内容から「知識候補」を作成できる
- 知識候補を保存できる
- 知識候補を「知識にする／見送る」と判断できる
- 選択した知識候補から正式な知識として保存できる


## E. 知識として整理する

### 完了

- AI回答から知識として整理できる
- 知識候補から知識として整理できる
- 保存済みかどうかを判別できる
- 重複保存を防ぐ仕組みがある
- 利用者向け表示では「Knowledge」ではなく「知識」を基本表記とする


## F. 知を育てる

### 完了

- 保存した知識を一覧表示できる
- 知識を検索できる
- 知識の詳細を確認できる
- 知識を編集できる
- 知識同士を結び付けることができる
- 知識同士の関係を設定できる
- 知識のつながりを一覧で確認できる
- 知識のつながりをグラフで確認できる
- 利用者向けの「Knowledge Network」「Knowledge Graph」等を
  「知識のつながり」に日本語化している


## G. 利用者向け用語

### 完了

- 利用者向け画面の Project 表記を見直した
- 利用者向け画面の Knowledge 表記を「知識」に統一した
- Knowledge候補 を「知識候補」に変更した
- Knowledge Type 等の技術的表現を日本語化した
- 内部クラス名・モデル名・変数名の Knowledge は変更せず、
  利用者向け表示だけを日本語化する方針とした


## H. データのローカル管理

### 完了

- 利用者データをSQLiteで端末内に保存する基本構造がある
- PAMS Companionのローカル中心設計を維持している

# 4. Version 2以降へ送る機能

以下は重要な機能であるが、Version 1の公開条件には含めない。

- TODO管理
- 将来の予定の管理
- 「今日の記録」を生活全体の入口として発展させる機能

- 知識ネットワークの高度な分析・可視化
- その他、Version 1公開後の利用者フィードバックを踏まえた機能拡張


# 5. Version 1 完成判定の進め方

完成判定は、一度に多数の項目を変更せず、
「要確認」の先頭から一項目ずつ確認する。

確認結果に応じて、

要確認 → 完了

または

要確認 → 未完了

へ変更する。

未完了となった場合は、その項目だけを実装・動作確認し、
完了後にGitへコミットする。
